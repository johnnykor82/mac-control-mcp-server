# Новый Mac → Mac Control → ChatGPT

Это последовательность ручной настройки нового Mac владельцем. Установка Mac Control сама по себе **не подключает Mac к ChatGPT**: нужны отдельные GitHub OAuth App, публичный HTTPS-адрес, запущенный remote MCP и добавление сервера в ChatGPT.

**Статус: экспериментальный remote OAuth.** Локальные проверки конфигурации и отказа анонимным запросам не подтверждают реальный вход. Независимая установка на новом Mac, живой GitHub OAuth, внешний Tailscale Funnel и разрешённая удалённая запись остаются непроверенными этапами релиза. Ни команды ниже, ни наличие этой инструкции не означают, что они уже успешно пройдены.

## 1. Подготовьте Mac и аккаунты

Понадобятся macOS, Python 3.9+ для запуска установщика, доступ к GitHub, Tailscale при выборе Funnel и аккаунт ChatGPT, которому разрешено добавлять собственные MCP-серверы. Для браузерных инструментов нужен Google Chrome и отдельный ChatBridge. Установщик создаёт изолированное окружение Python 3.13 через uv.

Mac Control предоставляет широкие права пользователя Mac. Прочитайте [SECURITY.md](../SECURITY.md) и изучите исходники до запуска. Рабочий каталог агента — правило поведения, а не системная песочница.

Все дальнейшие команды запускайте **локально в Terminal на подключаемом Mac**, из каталога проверенных исходников, если явно не указано другое. Не передавайте агенту Client Secret, OAuth-токены, ключ подписи или данные браузерной сессии в чате, скриншотах и логах.

## 2. Установите локальный MCP

Если репозиторий уже клонирован и Mac Control установлен, перейдите в его
каталог, выполните `git pull --ff-only` и `python3 scripts/install_mac_control.py --status`.
При необходимости обновите уже установленный Mac Control командой
`python3 scripts/install_mac_control.py --update`. Переходите к следующему шагу;
повторное клонирование и `--install` не нужны.

Для первой установки:

```sh
git clone https://github.com/johnnykor82/mac-control-mcp-server.git
cd mac-control-mcp-server
python3 scripts/release_preflight.py --json || [ "$?" -eq 2 ]
python3 scripts/release_audit.py --strict
python3 scripts/install_mac_control.py --plan
python3 scripts/install_mac_control.py --install
python3 scripts/install_mac_control.py --status
```

Продолжайте после успешной установки. Исключение для preflight с кодом 2 допускает отсутствие uv перед интерактивным bootstrap ChatBridge; другие ошибки необходимо устранить. Подробности зависимостей и восстановления — в [README](../README.ru.md#установка-на-macos).

По умолчанию установщик переиспользует совместимый ChatBridge или устанавливает закреплённый отдельный релиз. Если браузерные инструменты не нужны, используйте `--install --without-chatbridge` вместо `--install`. ChatBridge остаётся самостоятельным продуктом. Вход в его управляемый профиль ChatGPT нужен для браузерной сессии; он **не заменяет** подключение MCP в шаге 8.

Локальный stdio launcher предназначен для MCP-клиента на этом Mac. Для описанного здесь подключения из ChatGPT нужен отдельный remote HTTPS endpoint.

## 3. Продолжайте интерактивный мастер и выдайте права macOS

После `--install` в обычном Terminal мастер запускается автоматически. Если
шаг был отложен, установка выполнялась без интерактивного ввода или нужно
продолжить после исправления ошибки:

```sh
python3 scripts/install_mac_control.py --setup
```

В неинтерактивном режиме установка сообщает `pending_owner_interaction`, а не
завершённое подключение. `--update` обновляет локальный MCP и по умолчанию
переиспользует GUI helper без пересборки; мастер возобновляется через `--setup`.

GUI helper устанавливается по умолчанию отдельно как
`~/Applications/MacControlMCPServer.app`. Для его сборки и Unicode clipboard
helper нужны Apple Command Line Tools. Если их нет, выполните
`xcode-select --install`, вручную подтвердите диалог Apple, дождитесь завершения
и повторите установку. Mac Control не запускает скачивание автоматически.

Мастер запускает helper, запрашивает системные разрешения и проверяет его status.
Откройте **System Settings → Privacy & Security** и вручную разрешите helper
**Accessibility** и **Screen Recording**. Мастер открывает соответствующий
раздел настроек; если это не удалось, перейдите туда вручную. Следуйте запросу
macOS о перезапуске. Нажмите Enter для повторной проверки или S, чтобы отложить.
При отказе настройка остаётся `pending_gui_permissions`; продолжите через `--setup`.

Это разрешения TCC: установщик, GitHub OAuth и подтверждения ChatGPT не могут
выдать их за владельца. Проверяйте GUI отдельной несекретной операцией:
`system_info` не подтверждает Accessibility или захват экрана.
`--with-gui` явно разрешает пересборку проверенного owner-managed helper, после
которой macOS может потребовать TCC заново. `--without-gui` пропускает новую
установку GUI и TCC-шаг мастера. Для продолжения используйте `--setup --without-gui`. Уже включённый GUI сохраняется; для нового
релиза готовится clipboard helper. Неизвестный app не заменяется.

## 4. Выберите публичный HTTPS-адрес

Мастер проверяет локальные сетевые признаки и обращается к внешнему сервису
определения IP, затем спрашивает о белом IP. Echo IP, частные адреса или
совпадение адресов не подтверждают CGNAT либо доступность входящих соединений.
Уточните условия провайдера и проверьте HTTPS из другой сети.

Если белый IP и входящий HTTPS доступны, укажите окончательный адрес домена
вида `https://control.example.com`. Нужны DNS и доверенный TLS-сертификат.
После настройки OAuth и локальной проверки 401 владелец вручную настраивает
HTTPS reverse proxy на **TCP 443**, направленный к **127.0.0.1:3201**; при
необходимости пробрасывает на роутере только TCP 443. Порт 3201 остаётся
локальным: не открывайте его на LAN или публичном интерфейсе. Proxy должен
пропускать `/mcp`, OAuth metadata и callback, а не только MCP-путь.
Мастер не настраивает роутер, DNS, сертификат или proxy за владельца.

Если белого IP нет или ответ неизвестен, мастер предлагает Tailscale Funnel.
Существующий Tailscale переиспользуется; при его отсутствии владелец
устанавливает [официальный клиент macOS](https://tailscale.com/docs/install/mac).
Войдите вручную, подтвердите сетевые разрешения macOS и разрешите MagicDNS,
HTTPS и Funnel для устройства в tailnet. После этого введите `ГОТОВО` или `READY`
для проверки; пустой ответ откладывает настройку. CLI обнаруживается и внутри Tailscale.app.
VPN-маршруты, WireGuard и Exit Node не перенастраиваются.

Окончательный origin будет иметь вид `https://YOUR-DEVICE.YOUR-TAILNET.ts.net`.
Tailscale Serve доступен только внутри tailnet; для внешнего ChatGPT нужен
публичный Funnel. Публичный маршрут включается после защиты MCP в шаге 6.
Подробнее: [удалённый доступ](REMOTE_ACCESS_GUIDE.md).

## 5. Вручную зарегистрируйте GitHub OAuth App

Мастер покажет поля для окончательного HTTPS origin. Войдите в GitHub и
откройте **Settings → Developer settings → OAuth Apps → New OAuth App**:
[форма регистрации](https://github.com/settings/applications/new).
Нужен обычный OAuth App. Homepage URL — выбранный origin; callback должен
точно совпадать с `https://YOUR-HTTPS-HOST/auth/callback`.

Создайте приложение, получите Client ID и Client Secret. Продолжите мастер:
введите GitHub username либо используйте авторизованный `gh`, сверьте логин и
числовой ID, подтвердите `YES`. Введите Client ID локально, Client Secret —
только в скрытом запросе Terminal. Не передавайте секрет в чат или аргументах.
GitHub используется через FastMCP OAuthProxy с `read:user`, без доступа к
репозиториям; допускаются только настроенные числовые ID. Реальное владение
аккаунтом проверяется последующим OAuth-входом.

Файл `~/Library/Application Support/MacControl/MCPServer/data/remote_auth.json`
создаётся с правами `0600` и содержит секрет и случайный ключ подписи. Не
выводите его в чат или Git. Существующая конфигурация не перезаписывается;
при несовпадении origin мастер остановится. Смена адреса, приложения, ID или
ключа требует явной ротации владельцем. Проверка конфигурации не подтверждает
реальный OAuth. См. [GitHub OAuth](GITHUB_OAUTH_SETUP.md).

## 6. Автозапуск защищённого MCP и публикация HTTPS

После OAuth мастер устанавливает и запускает пользовательский LaunchAgent:
`~/Library/LaunchAgents/org.maccontrol.mcpserver.remote.plist`. Он обеспечивает
автозапуск remote MCP после входа владельца и использует launcher активного
релиза. Это не системный daemon: без входа владельца доступность не обещается.
Служба слушает только `127.0.0.1:3201`. Не запускайте одновременно отдельный
foreground MCP на том же порту.

Перед публикацией мастер проверяет локальный `/mcp`: анонимный запрос должен
вернуть HTTP 401 с `WWW-Authenticate`; OAuth issuer должен совпасть с origin.
Для Funnel требуется ввести **PUBLISH**. Существующие чужие маршруты не
заменяются; собственная проверенная публикация может переиспользоваться.
Для прямого подключения мастер ждёт настройки HTTPS proxy владельцем.
**Не публикуйте неавторизованный DEV-порт 3101.**

Затем проверяются публичные HTTPS discovery и отказ анонимному клиенту.
Незавершённый шаг остаётся pending; после исправления продолжите `--setup`.
Даже успешный публичный probe не подтверждает реальный GitHub OAuth или ChatGPT.
Состояние службы можно проверить локально:

```sh
python3 scripts/setup_remote_service.py --status
```

## 7. Проверьте внешний доступ и реальный OAuth

```sh
python3 scripts/install_mac_control.py --github-oauth-probe
python3 scripts/install_mac_control.py --github-oauth-login-test
```

Probe проверяет публичные HTTPS discovery и отказ анонимному клиенту. Login test открывает браузер, требует вашего реального согласия GitHub и вызывает `system_info` через публичный MCP. Успех probe не равен успеху login test. Даже успешный login test проверяет отдельный тестовый MCP-клиент; подключение ChatGPT нужно проверить следующим шагом.

Дополнительно проверьте внешний URL из другой сети и отказ другому GitHub-аккаунту, которого нет в разрешённом списке. До этого авторизационную проверку нельзя считать завершённой. Не пересылайте OAuth URL с кодами, токены и содержимое credential-файлов при диагностике.

## 8. Добавьте сервер в ChatGPT

Порядок интерфейса сверен 2026-10-29 с [официальной инструкцией OpenAI](https://developers.openai.com/api/docs/guides/custom-mcp-server). Доступность и права зависят от аккаунта, workspace и ограничений безопасности.

В веб-версии ChatGPT откройте **Plugins → + → Add custom MCP server**. Задайте имя, например `My Mac`, и в **Connection / Server URL** укажите:

```text
https://YOUR-DEVICE.YOUR-TAILNET.ts.net/mcp
```

Выберите **OAuth**, ознакомьтесь с предупреждением и создайте plugin. Установите его в свой аккаунт/workspace и выполните предложенный вход GitHub разрешённым аккаунтом. Не вставляйте GitHub Client Secret в чат: он уже сохранён на Mac для upstream OAuth. Совместимость конкретного OAuth-обмена ChatGPT с этим экспериментальным сервером должна быть проверена живым подключением.

В чате выберите установленный plugin через `@`. Для первой проверки попросите: «Через My Mac вызови только system_info и покажи результат». Проверьте инструменты и разрешения действий в настройках plugin. Конкретные названия меню и доступные режимы могут отличаться; если добавление сервера недоступно, проверьте ограничения аккаунта/workspace по официальной инструкции.

## 9. Подтвердите готовность и границы доступа

Подключение можно считать проверенным на этом Mac после успешного OAuth в ChatGPT и фактического ответа `system_info` от нужного компьютера. Затем отдельно проверьте только нужные возможности: браузер через ChatBridge, GUI после TCC и, при необходимости, создание и удаление одного временного файла в workspace с явным указанием владельца. Эти проверки пока не заявлены как выполненные разработчиком на новом Mac.

Есть три независимых уровня: OAuth определяет, кто может подключиться; macOS TCC разрешает доступ helper к интерфейсу и экрану; настройки ChatGPT определяют подтверждения действий. Разрешение одного уровня не отменяет остальные или автоматические ограничения платформы. Выбирайте режим подтверждений осознанно, без обязательного включения «разрешить всё».

Для локального наблюдения вызовов откройте ещё одно окно Terminal:

```sh
"$HOME/Library/Application Support/MacControl/MCPServer/current/bin/mclog"
```

Монитор показывает вызовы, ошибки и длительность; он не доказывает, что все права настроены. О содержимом журнала — [MCLOG.md](MCLOG.md).

Если связь пропала, последовательно проверьте: состояние owner LaunchAgent и вход владельца в macOS, HTTPS proxy либо Tailscale/Funnel, неизменный HTTPS-host и callback GitHub, `--github-oauth-check`, `--github-oauth-probe`, затем OAuth в ChatGPT. При ошибке GUI проверьте TCC; при ошибке браузера — самостоятельный ChatBridge. Сохраняйте в отчёте только статусы и несекретные сообщения об ошибках.
