# Возможности Mac Control: модули и практические сценарии

Mac Control MCP Server связывает авторизованного ИИ-ассистента с Mac владельца.
Он объединяет работу с файлами проектов, Git, терминальными сессиями, SSH,
интерфейсом macOS, браузером через ChatBridge и длительными задачами через Watcher.
Здесь описана версия beta.17 и условия, при которых её модули становятся доступны.
Наличие инструмента в списке ещё не подтверждает установку зависимости, вход
в аккаунт, выдачу разрешения или работоспособность внешнего соединения.

Точные параметры смотрите в [справочнике инструментов](TOOLS.ru.md). Установку
и подключение начните с [README](../README.ru.md). Полный пример работы
координатора и исполнителя приведён в [руководстве Watcher](WATCHER_GUIDE.ru.md).

## Что подготавливает обычная установка

| Модуль | Обычная установка | Дополнительное действие владельца или зависимость |
|---|---|---|
| Файлы, Git, диагностика, обслуживание | Входят в основной сервер | Настроить дополнительные корни проектов; репозитории и доступ к Git остаются вашими. |
| Рабочая папка агента и просмотр аудита | Создаются и устанавливаются автоматически | Подключить MCP-клиент; при необходимости открыть `mclog`. |
| Терминал и пакеты | Реализация инструментов входит в поставку | Явно включить терминал; установить Homebrew или tmux, если они нужны. |
| Нативный GUI-помощник | По умолчанию устанавливается или проверяется и используется повторно | Выдать разрешения «Универсальный доступ» и «Запись экрана». |
| Интеграция ChatBridge | Используется совместимый сервис или устанавливается отдельный закреплённый выпуск | Google Chrome, поддерживаемые API и вход в нужный аккаунт. |
| Watcher | Подготавливается при стандартной установке с ChatBridge | Войти в ChatGPT; зарегистрировать проекты и задачи. |
| Удалённый MCP | Средства настройки входят в поставку | Создать своё GitHub OAuth App, настроить доверенный публичный HTTPS и авторизовать клиент. |
| SSH и другие MCP-серверы | Клиентские инструменты входят в поставку | Настроить свои хосты, ключи, известные узлы и целевые серверы. |

Экспериментальный модуль `background_native` не включается при обычной установке.
Исторические документы DEV описывают дополнительные эксперименты, но не расширяют
поддерживаемый стандартный набор. GUI-инструменты обычного продукта используют
отдельно установленный нативный помощник.

## Единое место для работы агента

Рабочая папка по умолчанию:

```text
~/MacControlMCP/data/workspace
```

В ней создаются `projects`, `scratch`, `scratch/tmp`, `artifacts`, `downloads`
и `logs`. Инструкции сервера и инструмент `workspace_policy` предписывают агенту
сохранять здесь создаваемые проекты, клоны, тесты, загрузки и результаты.
Другие места используются по конкретному указанию владельца или для необходимой
системной настройки. Это правило работы, а не изоляция средствами macOS.

**Пример запроса:** «Создай папку исследования в рабочей папке агента. Отдели
исходные заметки от итогового отчёта и покажи созданные файлы».
Так удобно поручать агенту самостоятельные проекты, не смешивая временные
материалы с рабочим столом и существующими репозиториями владельца.

## Файлы проектов, поиск и правки текста

`project_roots` показывает разрешённые корни. Рабочая папка доступна под именем
`workspace`; дополнительные корни задаются владельцем в `allowed_projects.json`.
`fs_list`, `fs_stat`, `fs_read` и `fs_search` просматривают содержимое проектов.
Объём текста и вывода ограничен: обычное чтение и запись текстового файла
рассчитаны на размер до 512 КиБ. Ссылка на медиа не помещает весь бинарный файл
непосредственно в текстовый ответ.

`fs_write` создаёт или заменяет UTF-8-текст, а `fs_replace` заменяет ровно одно
совпадение. Для изменения существующего содержимого нужен его текущий SHA256.
Эта проверка compare-and-swap не позволяет незаметно перезаписать файл, который
изменился после чтения. При конфликте следует прочитать новую версию, согласовать
правку с её содержимым и повторить запрос. Для записываемого Python-текста
проверяется синтаксис до замены файла.

```text
fs_read(project="workspace", path="projects/demo/notes.md")
fs_replace(project="workspace", path="projects/demo/notes.md",
           old="Draft", new="Reviewed", expected_sha256="<хеш из чтения>")
```

Файловый API отклоняет выход за корень, символьные ссылки и чувствительные или
генерируемые пути, например `.ssh`, `.env*`, `.git` и `node_modules`.
Эти проверки относятся к данному API; включённый терминал и GUI имеют более
широкий доступ учётной записи Mac.

## Копии восстановления, перемещение и удаление

При замене существующего файла файловые инструменты сохраняют копию в
`data/backups/fs_recovery`. `fs_restore` восстанавливает выбранную копию с
проверками назначения. `fs_mkdir` и `fs_move` помогают организовать проект.
`fs_trash` требует ожидаемый хеш и сохраняет восстанавливаемую копию файла перед
удалением. Это не универсальный интерфейс рекурсивного удаления папок.

**Пример запроса:** «Измени конфигурацию с проверкой текущего хеша. Сохрани
полученный идентификатор резервной копии в отчёте, чтобы вернуть прежний файл».
Копии локальны и могут содержать исходные приватные данные. Они не заменяют
независимое резервное копирование и не гарантируют восстановление при поломке диска.

## Git с явной областью изменений

Git-инструменты показывают состояние, diff, историю и ветки; создают ветку;
добавляют конкретные пути в индекс; делают commit, fetch, pull только с
fast-forward и push. Выбранный корень проекта должен быть корнем репозитория.
В индекс передаются явные пути, а не неограниченный `git add -A`.
Для операций отключены Git hooks и интерактивный запрос учётных данных.
Доступ к remote и Git identity должны работать у пользователя, запустившего сервис.

**Пример запроса:** «Проверь разрешённый репозиторий, исправь описанную ошибку,
покажи diff и результаты тестов, затем закоммить только изменённые файлы».
`git_diff(staged=true)` позволяет проверить будущий состав коммита. Успешный
локальный commit не подтверждает успешный push или завершение удалённого CI.
Произвольные Git-команды возможны через явно включённый терминал.

## Терминал: отдельная команда или постоянная сессия

Терминал выключен, пока его приватная политика явно не разрешит доступ.
`terminal_capabilities` показывает это состояние. `terminal_access_configure`
изменяет настройку; включение разрешает shell от имени пользователя сервиса.
Выбор рабочей папки определяет стартовую директорию, но не ограничивает доступ shell.

`terminal_exec` запускает неинтерактивную zsh-команду с ограничением времени и
возвращает вывод. Инструменты постоянных сессий открывают, читают, перечисляют,
изменяют размер и закрывают tmux-терминалы, а также передают им ввод.
Это удобно для длительной сборки и команд с несколькими этапами взаимодействия.
Для интерактивных сессий требуется tmux. Временные файлы и кеши по умолчанию
направляются в рабочую папку агента.

**Пример запроса:** «Запусти сборку разрешённого проекта. Если нужен постоянный
терминал, сохрани сессию и сообщи её текущий вывод и код завершения».
Наличие сессии не доказывает завершение задачи. Команды и вызываемые ими скрипты
работают с правами учётной записи Mac.

## Разрешённые команды, тесты и Homebrew

Для более узкой автоматизации `approved_commands` и `execute_approved` используют
точные списки аргументов из локального `allowed_commands.json`. Вызывающий клиент
не передаёт произвольную shell-строку. `project_task` предоставляет конкретные
сценарии компиляции Python, pytest, npm test и npm build для разрешённого проекта.
Сами тесты и скрипты сборки могут выполнять код и обращаться к сети.

Пакетные инструменты проверяют наличие Homebrew и установленные формулы,
запускают установку формулы и показывают состояние фоновой задачи с хвостом журнала.
`package_install` принимает простое имя формулы: не URL установщика, cask, tap
или команду sudo. Homebrew должен быть установлен отдельно.
Установка формулы может выполнять установочные скрипты от имени пользователя Mac.

**Пример запроса:** «Проверь наличие tmux. После моего разрешения установи
формулу, дождись результата пакетной задачи и повторно проверь доступность».
Состояние queued означает начало работы; итог смотрите через `package_job_status`.

## SSH-профили, команды и проверка аутентификации

Доступны два сценария SSH: фиксированная диагностика локально настроенных целей
и управляемые профили для удалённых shell-команд и постоянных PTY-сессий.
`ssh_targets` и `ssh_diagnostic` используют `ssh_targets.json` и имена
диагностических команд. Инструменты профилей показывают SSH aliases и позволяют
регистрировать/подтверждать профили; `ssh_exec` выполняет удалённую команду,
а `ssh_pty_open` открывает интерактивную сессию. Для неё нужны инструменты
терминальных сессий и явное включение терминального доступа.

SSH использует ключи владельца и строгую проверку ключа хоста. Для нового сервера
нужна доверенная запись known_hosts: адрес в сообщении сам по себе не делает узел
доверенным. Удалённые команды имеют права пользователя входа на сервере,
которые могут быть очень широкими. `ssh_auth_diagnostics` и
`ssh_identity_inspect` проверяют метаданные аутентификации, имена и права файлов,
состояние агента и конфигурации, не читая содержимое приватных ключей.

**Пример запроса:** «Через уже разрешённый staging-профиль проверь место на диске
и состояние сервиса. До изменений сообщи, что обнаружено».
Установка не предоставляет SSH-ключи или готовый список production-серверов.

## Интерфейс macOS и снимки экрана

Нативный помощник предоставляет список дисплеев и окон, дерево Accessibility,
снимки экрана, открытие приложений, фокус, мышь, прокрутку, клавиши, ввод текста
и ожидание заголовка окна. Это полезно для приложений без подходящего API или CLI.
По умолчанию помощник находится в `~/MacControlMCP/apps/MacControlMCPServer.app`.
Обычная установка готового приложения не требует локальной компиляции Swift.

«Универсальный доступ» и «Запись экрана» — отдельные разрешения владельца macOS.
`gui_status` показывает разрешения и связь с помощником;
`gui_request_permissions` вызывает системный процесс запроса. Окно разрешения
может не появиться, и агент не может выдать себе TCC-разрешения за владельца.
Снимки и дерево Accessibility могут раскрыть любые видимые приватные данные.

**Пример запроса:** «Открой редактор документа, проверь текущее окно и внеси
запрошенную правку. Перед отправкой или публикацией спроси меня».
GUI-действия могут затронуть приложение, в котором сейчас работает владелец.
Глобальное нажатие клавиши или ввод текста нельзя считать фоновой операцией.

## Браузер через независимое приложение ChatBridge

Инструменты `background_browser_*` создают браузерные сессии с секретом доступа,
открывают страницы и выполняют действия, читают снимки структуры, получают
изображения, перечисляют разрешённые сессии, закрывают и повторно открывают их.
Поддерживаются click, fill, press, scroll и операции с вкладками, доступные
в ChatBridge. Секрет сессии — приватный материал для доступа.

Mac Control передаёт HTTP-запросы ChatBridge, который владеет Chrome и профилями.
Mac Control не запускает отдельный Playwright-браузер и не подключается к CDP.
Фоновый API не переключается незаметно на ввод через обычный GUI.
Вход в аккаунт, структура страницы, ограничения запросов и проверки доступа
сайта могут остановить задачу. Неопределённый результат действия нужно проверить
до повторного клика или отправки формы.

**Пример запроса:** «Прочитай три публичные страницы продуктов в фоновых
браузерных сессиях и сохрани сравнение в workspace. Не отправляй формы».
Отсутствующий или несовместимый API ChatBridge возвращает ошибку, а не запускает
второй браузер. Смотрите [заметки об интеграции](CHATBRIDGE_BROWSER_MIGRATION.md):
датированные состояния DEV в старых документах являются историческими сведениями.

## Разговоры ChatGPT и совместимость с orchestrator

Сохранённые имена `chrome_chat_*` и `chrome_orchestrator_*` предназначены не для
обычного веб-сёрфинга, а для связи задач с разговорами ChatGPT через Sessions API
ChatBridge. Они создают или подключают чат задачи, отправляют запрос, читают или
ожидают результат, сохраняют отчёт и поддерживают состояние совместимости.
`chrome_orchestrator_launch` проверяет gateway, а не запускает Chrome.
Очистка и архивирование следуют возможностям адаптера; это не управление любыми
браузерными вкладками. Точное поведение смотрите в описании выбранного инструмента.

Интеграция использует авторизованную веб-сессию ChatGPT. Это неофициальный способ,
не официальный OpenAI API. Mac Control не предоставляет подписку ChatGPT,
разрешения аккаунта, доступ к моделям или дополнительную квоту запросов.

## Watcher: файловые отчёты и завершение в браузере

Watcher хранит проекты и задачи в приватной SQLite и направляет уведомления
в зарегистрированный чат координатора. Новая установка начинает с пустого состояния.
Это планировщик и доставка, а не дополнительная модель ИИ или вычислительный пул.

Файловый режим использует `watcher_register_file_task` и отчёты с ревизиями через
`watcher_submit_report`. Отдельные секреты разрешают отправку и возобновление.
Отчёты неизменяемы, проверяются по SHA256 и содержат до 80 КиБ UTF-8-текста.
`checkpoint` фиксирует прогресс; `needs_input`, `blocked` и `completed` уведомляют
координатора. Он читает отчёт, проверяет результат и подтверждает получение.
После блокировки или вопроса файловая задача явно возобновляется в том же чате.

Браузерный режим использует `watcher_register_task` и подтверждённые ChatBridge
сведения о завершении. После проверки результата и подтверждения доставки
`watcher_followup_browser_task` продолжает того же исполнителя со стабильным
ключом запроса и сохранением прежних отчётов. Проверяется точное соответствие
сессии и чата. Неизвестный результат доставки нельзя слепо отправлять повторно.
Подробности — в [полном руководстве](WATCHER_GUIDE.ru.md).

## Отложенные проверки, пауза и доступность

`watcher_schedule_wakeup` сохраняет отложенную проверку для подтверждённого чата.
Назначение задаётся точным URL или проверенным маркером
`WATCHER-CHAT-<32 строчных hex-символа>`. Маркер определяет адресата, но не даёт
разрешение на произвольную работу. Инструменты list/get/cancel/ack управляют
проверками, а явные pause/resume — проектами. Одна проверка не создаёт цикл повторений.

**Пример запроса:** «Через пятнадцать минут проверь реальный результат задачи
и сообщи в этом разговоре. Не считай последнее сообщение исполнителя доказательством».
Для доставки Mac должен работать, пользователь — войти в macOS, а сеть — быть
доступной. SQLite переживает перезапуск; занятый чат, cooldown провайдера и офлайн
задерживают работу. Без активных задач Watcher работает локально;
все браузерные операции выполняет ChatBridge.

## Другие MCP-серверы и локальная диагностика

`mcp_targets` показывает настроенные владельцем серверы. `mcp_bridge_list`,
`mcp_bridge_read` и `mcp_bridge_call` читают каталог и вызывают разрешённые
локальные HTTP- или stdio-MCP-серверы. Для read-вызова нужна аннотация read-only
целевого инструмента; это декларация, а не независимая проверка его поведения.
Передача медиа учитывает настроенные корни и ограничения транспорта.

`system_info`, `machine_health`, `network_listeners` и `process_snapshot` помогают
проверить Mac. `local_http_probe` обращается к определённым локальным портам,
а не сканирует произвольную сеть. `launchd_status` и `launchd_restart` используют
список разрешённых сервисов. Доступность диагностики не разрешает сама по себе ремонт.

## Удалённый доступ, обслуживание, журналы и жизненный цикл

Локальный MCP запускается установленным stdio-launcher. Удалённая настройка
использует GitHub OAuth App владельца и проверку владельца; MCP слушает loopback
за публичным HTTPS. Возможны свой домен/TLS/reverse proxy или Tailscale Funnel.
Для публикации Funnel требуется отдельное подтверждение. Настройка не меняет
существующий VPN; внешний IP от echo-сервиса не доказывает доступность входящего HTTPS.
Смотрите [OAuth](GITHUB_OAUTH_SETUP.md) и [удалённый доступ](REMOTE_ACCESS_GUIDE.md).

Инструменты обслуживания показывают диагностику и журналы сервисов, ищут
метаданные аудита, читают поставляемый код и файлы workspace, пишут только в
разрешённую ими область workspace и перезапускают проверенный собственный remote-сервис.
`custom_query` и `custom_command` вызывают поставляемые обработчики с теми же
флагами доступности; новый произвольный workspace-плагин не загружается в сервер.

`mclog` — поставляемая терминальная панель аудита только для чтения.
Публичный аудит содержит имена инструментов, время, статус и длительность,
без аргументов и тел ответов. Это не означает отсутствия содержимого во всех
локальных данных: отчёты, копии, профили браузера, вывод терминала и журналы
пакетов/сервисов могут содержать приватную информацию.
Смотрите [mclog](MCLOG.md), [безопасность](../SECURITY.md) и [состав установки](INSTALL_CONTENTS.md).

Установщик поддерживает plan/install/setup/update/status/rollback/uninstall.
Версионные каталоги и ссылки `current`/`previous` обеспечивают откат; данные
владельца сохраняются. Обновление по умолчанию повторно использует проверенный
GUI-помощник, сохраняя его TCC-идентичность. ChatBridge остаётся независимой установкой.
Это экспериментальное ПО: проверяйте реальные результаты, доступ к аккаунтам
и разрешения перед тем, как полагаться на автоматизированный процесс.
