# Отдельный каталог проектов Mac Control — beta.22

## Устройство

Установка `~/MacControlMCP/` содержит версии, GUI, зависимости, настройки,
служебные журналы, временное состояние и резервные копии самого Mac Control.
Проекты, исходники, пользовательские базы и результаты работы агентов
хранятся отдельно, по умолчанию в `~/AgentWorkspace/`:

```text
~/AgentWorkspace/
  projects/   # репозитории и данные проектов
  shared/     # общие материалы
  artifacts/  # результаты и сборки
  downloads/  # загрузки агентов
  scratch/    # временные файлы, тесты, кеши и логи проектов
```

Папка принадлежит пользователю macOS. Это расположение по умолчанию,
**не песочница**: явно разрешённые операции за её пределами сохраняются.
Разработка (MCP-Dev) по умолчанию использует отдельный `~/AgentWorkspace-Dev`.
Для нестандартного префикса установки каталог проектов создаётся рядом с ним.

Настройка `workspace_root` хранится в файле `<installation>/data/config/workspace.json`
с правами `0600`, вне сменяемых релизов.

## Команды

```sh
maccontrol workspace status
maccontrol workspace set /Volumes/ExternalDisk/AgentWorkspace
maccontrol workspace inventory --from ~/chatgpt-mcp/workspace
maccontrol workspace migrate --from ~/chatgpt-mcp/workspace --name old-server
```

`workspace migrate` без `--execute` выполняет только dry-run, оценивает размер,
ссылки, SQLite/WAL, свободное место и LaunchAgents, в которых встречается
путь источника. Для явного копирования:

```sh
maccontrol workspace migrate --from ~/chatgpt-mcp/workspace --name old-server --execute --yes
```

Содержимое будет скопировано в `~/AgentWorkspace/projects/old-server/`.
Исходники остаются **нетронутыми**, конфигурации чужих служб не переписываются.
Перед переносом работающих сервисов отдельно проверить абсолютные пути,
переменные окружения и порядок перезапуска. SQLite-файлы копируются
через SQLite backup API, включая подтверждённые WAL-транзакции; `-wal/-shm`
не переносятся как несогласованные бинарные снимки.

Символические ссылки копируются как ссылки, права и времена файлов сохраняются.
Результат проверяется SHA-256 для обычных файлов и `PRAGMA quick_check`
для SQLite. При ошибке неполная промежуточная копия удаляется; исходный каталог
остаётся. Не копировать подключённые тома, если путь недоступен.

## Обновление, откат и удаление

`maccontrol update` не меняет `workspace_root` и не переносит проекты.
`maccontrol rollback` сохраняет конфигурацию; откат на старый релиз,
который ещё не поддерживает внешний workspace, блокируется, чтобы не
скрывать проекты от агента. `uninstall` сохраняет все пользовательские файлы.
`uninstall --all` удаляет только собственную установку и её data, но
**никогда** не удаляет внешнее рабочее пространство. Если старая установка
ещё содержит файлы в `data/workspace`, полное удаление блокируется до
отдельной миграции.

В существующей установке с непустой старой рабочей папкой Mac Control
сохраняет прежний путь до явного переключения. Пользовательские данные
**не перемещаются автоматически**. `maccontrol workspace set` только
меняет путь; перемещение выполняется отдельной командой.

Отключённый внешний диск не заменяется автоматически локальной пустой папкой.
Нужно снова подключить том и проверить `maccontrol workspace status`.

### Порядок миграции старого сервера

1. Инвентаризация и dry-run без изменений.
2. Анализ зависимых LaunchAgents, скриптов и сервисов.
3. Резервная копия на независимом носителе с проверкой восстановления.
4. Согласованное копирование данных и SQLite с последующей проверкой.
5. По одному изменять пути и тестировать сторонние сервисы — **только
   в рамках отдельной явно разрешённой операции**.
6. После проверки — переключение `workspace_root`. Старые данные оставить
   на месте до отдельного решения об их удалении.

В beta.22 не запускаются операции над production, Tailscale,
существующими VPS/SSH-серверами и сторонними сервисами.
