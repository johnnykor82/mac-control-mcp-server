# ТЗ: Mac Control в общем Tailscale Funnel HTTPS:443

Статус: согласовано для разработки и локальных тестов; публикация маршрутов на рабочем сервере пока не разрешена.

1. Если HTTPS:443 уже обслуживает другие сервисы, мастер устанавливает новый Mac Control по свободному префиксу (предпочтительно `/maccontrol`), не изменяя корень `/` и остальные маршруты.
2. URL нового MCP: `https://<hostname>/maccontrol/mcp`. OAuth endpoints расположены под `/maccontrol`; специальные OAuth discovery endpoints имеют отдельные точные пути `/.well-known/.../maccontrol` и не конфликтуют со старым MCP.
3. Уже установленные копии и их OAuth issuer не меняются автоматически при обновлении. Смена URL — отдельная миграция после проверки.
4. Установщик анализирует `tailscale funnel status --json` и `tailscale serve status --json`, проверяет пути, совпадения и активные службы. При сомнениях ничего не меняет.
5. Публикация после проверки localhost OAuth и 401, явного согласия владельца, снимка состояния. Добавлять только нужные маршруты; после каждого действия сравнивать чужие пути; при ошибке удалять исключительно новые маршруты, не вызывая `reset`.
6. Тесты: чистая и совместная установка (10 существующих сервисов), метаданные и callback OAuth, конфликт путей, повторение установки, частичная ошибка, откат, сохранность проектов и чужих маршрутов.


## Проверенная семантика Tailscale

Исходники Tailscale подтверждают: `serveWebHandler` удаляет mount point из пути HTTP-запроса перед передачей на proxy backend. Поэтому установщик передаёт целевой URL **с таким же префиксом**, например для внешнего `/maccontrol/mcp` используется `--set-path=/maccontrol http://127.0.0.1:3201/maccontrol`. Для точного discovery endpoint действует то же правило. Без этого FastMCP получил бы ошибочный URL и OAuth не заработал бы.
