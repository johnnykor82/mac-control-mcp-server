# Mac Control MCP: workspace-first agent instructions

These instructions are part of the **MCP server instructions**, appear in
descriptions of write-capable tools and are discoverable with the read-only
`workspace_policy` MCP tool. The owner can copy them into any agent's own
system/project instructions if its MCP client does not display server
instructions reliably.

## Working directory — mandatory default

Mac Control MCP Server has one dedicated agent work area:

`~/Library/Application Support/MacControl/MCPServer/data/workspace`

The installer creates these paths inside that area:

| Subdirectory | Use |
| --- | --- |
| `projects/` | Repositories, cloned projects, builds and project documents |
| `scratch/` | Temporary input/output, disposable experiments |
| `scratch/tmp/` | Temporary files generated by the shell and CLI tools |
| `artifacts/` | Completed results the owner may copy or publish |
| `downloads/` | Files fetched by an agent |
| `logs/` | Agent/project logs, transcripts and diagnostics |

Use the MCP project name `workspace` by default. Filesystem tools accept a
relative path such as `projects/my-app/README.md`; terminal operations
default to `project="workspace"`, and the installer provisions `TMPDIR`,
`TMP`, `TEMP` and `XDG_CACHE_HOME` for shell operations.

**Do not use** the home directory, Desktop, Documents, ordinary Downloads,
`/tmp`, arbitrary `~/dev` or application folders for agent-generated
projects, Git clones, scratch files, exports or routine logs.

### Exceptions

The agent may read other authorized directories, inspect running services,
read system settings and use other Mac Control capabilities as before.

Writing outside the agent workspace is only allowed when:

1. **The owner expressly instructs the agent** to write to a particular
   destination for the task, naming the destination and its purpose; or
2. **The requested system integration cannot reasonably be performed
   inside the workspace**, such as installing a LaunchAgent under
   `~/Library/LaunchAgents`, a signed application under
   `~/Applications`, adjusting macOS settings, or changing a specifically
   requested service configuration.

Even for exception 2, create source files, drafts, staging files and backups
*inside* workspace and write only the final required system file outside.
Tell the owner what was written and why.

A command that can write outside workspace is **not** permission to choose
arbitrary outside destinations. The instruction is a convention for
authorized agents, **not an OS-level security sandbox**; the user can grant
full capabilities and explicit external-write exceptions.

### Example

**Correct:** clone to `workspace/projects/example`, run tests using its
subdirectory, write temporary reports in `workspace/scratch`, produce final
archive in `workspace/artifacts`, and install a necessary LaunchAgent only
when the owner requested an auto-start service.

**Incorrect:** clone to `~/example`, build in `/tmp/example`, write
generated data to Desktop and scatter service script backups among random
system directories.

### Completion report

Every agent should include in its final task summary:

- Worktree/project and created artifacts inside workspace.
- Any writes *outside* workspace, their locations, and direct user
  instruction or system-integration reason.
- Temporary files that were removed or still require cleanup.

## Existing owner data

**Do not move or delete existing projects automatically.** The policy
affects newly started tasks. On an already-used Mac, inventory external
agent-created files first, determine which services depend on them, create
backups and request the owner's explicit migration approval.

## Other services

Mac Control application configuration, release archives, secrets and runtime
socket data live under the Mac Control MCP Server application data root outside workspace,
because they are **software installation state**, not agent-generated project
content. ChatBridge owns its own service installation and browser profiles.

The private Stable installation has separate owner-specific settings; this
policy is wired into the **new Mac Control MCP Server release**, not retroactively into
running Stable or installed DEV.
