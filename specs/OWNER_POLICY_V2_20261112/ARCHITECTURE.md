# Architecture 1.0 — 2026-11-12
Agent-facing default policy is mandatory in tool descriptions: AgentWorkspace for every agent-created file by default; use paths beyond it only on explicit user authorization for the particular task. The installed Mac Control authenticates its owner and records task-specific audit_context as evidence, but audit_context alone is not a grant. Avoid inventing a new persistent grant file or claiming a security guarantee that an unrestricted shell under the same macOS account cannot enforce. Individual tool paths are checked for traversal/symlink safety, not for membership in a fixed root allowlist. Authorization is evaluated from actual owner instructions before tool execution.
Use existing root resolution/CAS/symlink safeguards; root canonicalization and no workspace traversal. For unrestricted tool access under approved task, rely on per-task scope, not hardcoded allowed_* lists.
SSH: client authentication may use any owner-accessible key in current user context; server authenticity uses system known_hosts or first-contact fingerprint/TOFU, refusing changed known keys. Permit direct host specs. Separate SSH capability authorization from connection selection. Never print private keys.
Each functional domain uses its own adapter, but shared policy centralizes scope decisions: core local_http diagnostics/process/task/logs; files/git/terminal; SSH; packages; browser/native/GUI/bridge/launchd; maintain Watcher reliability semantics unchanged.
No rewrite of production in-place: isolated worktree -> staged CI/test release -> verified package with unchanged native GUI if possible -> official update --without-chatbridge --without-gui on both hosts with fresh backup and read-only reconciliation after MCP restart. Previous immutable source retained. All tests are side-effect-free or isolated.
